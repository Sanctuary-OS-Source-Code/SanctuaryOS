## The Glassmorphism & Core Stability Overhaul


### Architecture/Bug Fixes
- **Wayfinder Post Management (Silent Failure):** Fixed a critical bug in `WayfinderPostsEditor` where creating or deleting Dispatch/Alert posts would silently fail (showing "Transmission Updated!" but not actually saving the data). The editor now correctly routes updates and deletions through the OS Edge Function proxies (`secure_upsert_cloud_file`, `secure_delete_cloud_file`) to bypass game database RLS limitations, and explicitly catches empty returns to prevent silent false-positives.
- **Edge Function Proxy (23505 Duplicate Key):** Updated the `game-gateway` Edge Function to explicitly intercept and safely ignore `23505` (Duplicate Key Constraint) violations during generic `upsert_cloud_file` operations (such as recording a post view). This prevents non-critical unique constraint errors from bubbling up to the client and polluting the console when users view posts they have already seen.
- **Game Database Authentication (401 Unauthorized):** Added strict `session.access_token` validation to the OS Edge Function proxies to completely eliminate the flood of 401 Unauthorized errors caused by unauthenticated users or expired sessions triggering the view logger. Fixed an issue where actions on Mason profiles and feeds (Following, Liking, and Viewing posts) were failing with a 401 error. Replaced direct client-side insertions with the dedicated OS Edge Function proxies (`secure_upsert_cloud_file`, `secure_delete_cloud_file`, `secure_toggle_mason_follow`) to securely route operations cross-project using the appropriate Service Role keys.
- **Hero URLs (Post Editors):** Fixed a critical parsing bug where Hero URLs would get wiped out when editing existing posts if the URL was initially inserted as standard Markdown or HTML. Updated the regex in `extractPostImage` to properly extract newlines and unified the `rawContent` stripper across `MasonPostsEditor`, `WayfinderPostsEditor`, and `KeeperPostsEditor` to enforce precise regex replacement that catches and cleans up all format variations correctly.
- **Mason Profile Hub Layout:** Repaired a severe layout overlap issue in the Mason Profile Overview. Replaced the error-prone Flexbox (`flex-col xl:flex-row`) wrapper with a robust CSS Grid implementation (`grid-cols-1 xl:grid-cols-[1fr_480px]`) for the COMM-LINK and SHOWCASE panes, completely eliminating any possibility of horizontal collapsing and rendering overlap.
- **Mason Profile Header UI:** Repaired a layout squishing bug in the profile header where the action buttons competed with the bio text for flex space. Migrated the header wrapper to a structured CSS Grid (`grid-cols-1 xl:grid-cols-[auto_1fr_280px]`), ensuring the buttons are strictly constrained to 280px while the bio text correctly fills the remaining space without wrapping prematurely.
- **SidePanel Hierarchy Overhaul:** Completely rewrote the visual stacking logic for `SidePanels`. Parent panels now beautifully and seamlessly fade away completely when their child panels are spawned (like navigating from Chameleon Library -> Aesthetic Matrix). This removes all visual stacking overlaps and guarantees a flawless user experience, and fixes a major bug where React's bottom-up DOM committing was inverting the visual hierarchy.
- **SidePanel Portals Alignment:** Fixed a massive logic failure in the `SidePanel` component where nested portals were being appended to the bottom of the `body` because `<div id="sa-portals">` was missing from `index.html`. Injected the missing div into the root HTML and deployed a new robust sibling CSS selector (`:has(~ .sa-side-panel-wrapper)`) to natively hide underlying `.sa-side-panel-window` elements while perfectly preserving their backdrops. This completely eradicates the messy overlapping UI when multiple modals or panels stack on top of each other.
- **Theme Image Management:** Added a beautiful new built-in gallery for previously installed local custom background images inside the Aesthetic Matrix (Chameleon Editor) panel. Also shrank the obnoxiously large upload button into a compact header toolbar.
- **Database Architecture (Themes):** Deployed a new `sanctuary_theme_images` SQL architecture to store custom theme backgrounds for global sharing.

### Architecture
- **React Portal Stability (Dropdowns):** Completely resolved an OS-wide bug where dropdowns and context menus would either fail to render (hidden) or incorrectly render at `top: 0, left: 0`. Migrated all `createPortal` instances to a dedicated `<div id="sa-portals">` managed safely *inside* the main React app tree in `App.tsx`. This permanently guarantees perfectly mapped coordinates by locking them inside the exact same React containing block without being trapped by `App` bounds or destroyed by external `document.body` modifications.
- **FilterTabs & Dropdown Stability:** Re-engineered `FilterPopover` and `HubTabDropdown` to use pure `absolute` positioning instead of `fixed` positioning for their menus. This permanently fixes an issue where side panel CSS transforms (like sliding animations) would incorrectly trap fixed-positioned dropdowns, causing them to render off-screen or appear as a blank space. The dropdowns now correctly anchor directly beneath their toggle buttons and seamlessly perform left/right bounds checking to avoid overflowing the viewport.

### Built-In Core Themes
We completely overhauled the default theme offerings to leverage the new true-glass engine. Every default theme now features a bespoke generated background image that flawlessly compliments its color palette and UI lighting model.
- **The Sims 4 Pilot Theme**: Introduced a dedicated core preset for The Sims 4. Replaced the initial dark-mode cyberpunk concept with a bright, friendly, Maxis-match inspired glassmorphism background featuring floating Plumbobs. The OS UI palette has been fully inverted for this theme, featuring crisp whites, airy frosted glass, deep text for readability, and iconic Plumbob Green accents.
- **Architect (Flagship Dark):** The ultra-premium default dark mode. Features pristine frosted glass (`glassOpacity: 5%`, `glassBlur: 24px`), a pitch black backdrop, and sleek deep-space aesthetics with cool icy blue accents (`#38bdf8`).
- **Radiant (Flagship Light):** The gorgeous default light mode. Features crisp whites (`bg: #fdfdfd`), airy glass panels, and vibrant pink accents (`#ec4899`) that create a clean, high-contrast, premium daytime experience.
- **The Sims 4 (Pilot Game):** A dedicated, bright, Maxis-match inspired glassmorphism preset featuring floating Plumbobs. The UI palette is inverted for a friendly, cozy feel with crisp whites, deep slate text for readability, and iconic Plumbob Green accents (`#5ac126`).
- **Aurora:** A vibrant, dark-toned aesthetic utilizing deep cyan (`#06b6d4`) accents and extremely faint glass panels (`10% opacity`) that allow the background's rich colors to shine through without overwhelming the UI.
- **Bunker:** An aggressive, retro-terminal hacker theme with scanlines, stark contrast, and zero-radius hard corners. Features pure matrix green (`#00ff41`) text and borders against absolute black backgrounds (`bg: #020602`). (And yes, we kept the humans out of the Bunker.)
- **Miami Vice (Synthwave):** An incredibly stylized, outrun-inspired aesthetic. Features deep purple backdrops (`bg: #050110`), neon pink accents (`#f92aad`), and heavily frosted, dark-tinted panels (`glassOpacity: 20%`).
- **Dracula:** A developer-favorite, high-contrast dark theme utilizing the iconic Dracula palette with vivid purple accents (`#bd93f9`), green successes, and red dangers, wrapped in a comfortable blue-grey darkness.
- **True Glass:** A pure, brutalist showcase of the glassmorphism engine. All solid backgrounds and sidebars are stripped away (`transparent`), forcing the entire UI to render solely using background blurs and faint white borders against whatever background image the user supplies.

- **Workspace-Wide Hover Stability**: Eliminated the random flickering and wobbling hover glitches across all cards and components in the OS by systematically removing all -translate-y hover effects, which were causing hitboxes to shift away from the mouse cursor on overflow-hidden elements.
