## TITLE

### Security & Architecture
- **Identity Matrix Role Segregation:** Enforced strict database context linking and role constraints for the Identity Matrix across different Hubs. Wayfinder and Oversight Hubs now correctly pull from the localized Spoke Database. The Oversight hub was locked to prevent visibility or modification of Wayfinder/Oversight roles (only allowing Citizen, Mason, Architect), while the Wayfinder hub retains full access to all Spoke roles. Keepers Core correctly remains linked to the global OS database with access limited strictly to Citizen, Keeper, and Admin roles.
- **Visibility Rules & Content Safeguards**: Overhauled `Nexus.tsx` queries to strictly surface mods with `compliance_tier = 0` and appropriate public statuses (`stable`, `unstable`, `corrupted`, `pending`). Configured Blueprint visibility and `Lab.tsx` cloud interactions to similarly limit fetches to `compliance_tier = 0` assets and approved tags, completely hiding queue items from unauthorized feeds.
- **Dynamic Schema-Driven PE Parsing:** Overhauled `rip_game_version` in the Tauri backend to automatically extract standard PE file version metadata (like `FileVersion`) natively from game executables (`.exe`) using the `pelite` Rust crate. This completely avoids PowerShell subprocesses, removing a common AV heuristic trigger and improving radar sweep performance. The parser intelligently utilizes `executable_names` from the active master schema (e.g. `sims4.json`) to locate predefined binaries first (like `TS4_x64.exe`). It falls back to scanning the target directory for the largest `.exe`—aggressively filtering out known crash handlers, redistributables, and anti-cheat binaries—before finally relying on the schema-defined `.ini` manifest (`version_extraction.relative_path`) if native PE extraction fails.
- **Editor Asset Extraction:** Extracted the asset fetching, searching, and `SidePanel` UI logic into a new shared abstraction, `LinkAssetSidePanel`. Successfully migrated all 6 editor components (`WayfinderPostsEditor`, `KeepersWebNewsEditor`, `KeepersWebDirectivesEditor`, `KeepersDispatchEditor`, `KeeperPostsEditor`, `MasonPostsEditor`) to use this standardized shared component, ensuring consistent tier-0 mod filtering globally.
- **Global Documentation & Schema Sync:** Synchronized 7 core architecture documents and SQL schemas (`schema_os.sql`, `schema.sql`, `Citizen Guide.md`, `Master Architecture & Feature Document.md`, `Sanctuary OS Forking & Architecture Guide.md`, `Compliance Protocol.md`, and `Partners Agreement.md`) to reflect recent systemic changes. Added the `hardware_bans` table to the OS schema and the `mod_meta` JSONB column to Blueprints. Deprecated all legacy references to Rust DBPF parsers in favor of the dynamic DB-driven expansion models, and updated the Nuclear Override documentation to reflect the new decoupled HWID privacy logic.
- **Hardware Ban Decoupling:** Reworked the Hardware ID (HWID) banning logic to enhance privacy and security. HWIDs are no longer persistently tracked or updated on user profiles upon login. Instead, a new dedicated `hardware_bans` table in the Core OS database stores HWID hashes only when a ban is explicitly triggered (e.g., via Nuclear Override or Malware Evasion). Login checks now cross-reference this table and enforce bans across both the Core OS and Spoke (Game) databases dynamically without requiring continuous tracking of the user's hardware signature.
- **OS-Wide Mobile Filter Architecture:** Refactored the core `ScreenUtilityBar` engine to use a new `MobileFilterGroup` bottom-sheet on mobile devices. This automatically collapses all secondary filters, dropdowns, and actions into a sleek bottom sheet on over 33 screens OS-wide, massively improving mobile header layouts and reclaiming vertical real estate.
- **Comm-Link Mobile Layout Fix:** Updated the mobile filter layout in the Comm-Link Feed (`GlobalFeed.tsx`) to directly align with the sleeker styling of the Nexus Tab. Replaced the generic `ScreenUtilityBar` wrapper with native nested `SearchBar` and `FilterPopover` components inside the `ViewHeader` to ensure the filters properly consolidate into a sleek dropdown sheet rather than crowding the center of the mobile viewport.
- **Comm-Link Feed Overview Rework:** Redesigned the Stat Tiles on the Comm-Link Feed overview screen to be much more engaging and actionable. The tiles now track "Recent Following," "Recent Global," "Interactions," and "Your Network," directly linking out to their respective tabs or a newly built `MasonFollowingSidePanel` to let users quickly manage and browse the masons they follow. Additionally, the core global feed searchbar now intelligently filters by mason profiles (display name and username) alongside standard text content.
- **Offline Metadata Persistence:** Upgraded the Blueprint (PlaySet) import and export engines to natively support full "Local Dossier" metadata overriding. Custom metadata (like `author` and `url`) assigned to "ghost" strings (missing mods) via the Local Dossier (`sanctuary_local_overrides`) is now dynamically injected into the Blueprint during export. Crucially, when a user imports a Blueprint with this custom metadata, it is securely persisted inside the PlaySet schema as `modMeta`, ensuring custom creator URLs remain fully intact even when shared peer-to-peer. The Ghost Strings and Missing Imports UI alerts now intelligently fall back to the global cloud Registry database for URLs and authors if offline metadata is absent.
- **Blueprint Game Identity:** Blueprint (PlaySet) exports now dynamically embed the `game_id` and `game_name` of the active workspace they were exported from, allowing the OS to accurately identify the target environment when the `.json` file is later imported.
- **Local DBPF Parser Deprecation:** Completely removed the local DBPF Rust parser from the codebase (`dbpf.rs` and `parser.rs`) and migrated the Conflict Radar and Explicitly Local logic to fully rely on the dynamic, DB-driven expansion model. This eradicates flakey parsing errors and unifies the schema architecture for easier game integration.
- **Hub Components Migration:** Completed a massive architectural migration of all legacy Hub components (Oversight, Communications, Chameleons, Settings, Wayfinders, and Masons) to the new `ElevatedHubLayout` and `UniversalCard` standards. This fully eradicates custom layout hacks, unifies the visual hierarchy, centralizes utility/filter bars, and guarantees consistent responsive behavior across the entire OS.
- **Spoke Database UUID Linkage:** Overhauled the data architecture for Game Spoke databases (e.g. `nexus_assets`, `nexus_reports`, `blueprint_reports`) to strictly bind records to active user UUIDs (`author_id`, `reporter_id`) rather than relying exclusively on string usernames. This permanently protects content ownership and telemetry mapping in the event of user profile name changes.
- **Finalized Hub Layout Migration:** Completed the final manual migration phase for `SADefcon`, `KeepersWebLegalEditor`, `KeepersWebNewsEditor`, `KeepersWebDirectivesEditor`, and `SAComplianceOversight`. Ensured all hub components implement the standard `renderLanding` overview tab, numerical badge counts powered by frontend dataset `.filter()` logic, and strict Lexicon key mapping.
