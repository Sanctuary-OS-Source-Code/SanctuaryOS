## TITLE

### Security & Architecture
- **Global Documentation & Schema Sync:** Synchronized 7 core architecture documents and SQL schemas (`schema_os.sql`, `schema.sql`, `Citizen Guide.md`, `Master Architecture & Feature Document.md`, `Sanctuary OS Forking & Architecture Guide.md`, `Compliance Protocol.md`, and `Partners Agreement.md`) to reflect recent systemic changes. Added the `hardware_bans` table to the OS schema and the `mod_meta` JSONB column to Blueprints. Deprecated all legacy references to Rust DBPF parsers in favor of the dynamic DB-driven expansion models, and updated the Nuclear Override documentation to reflect the new decoupled HWID privacy logic.
- **Hardware Ban Decoupling:** Reworked the Hardware ID (HWID) banning logic to enhance privacy and security. HWIDs are no longer persistently tracked or updated on user profiles upon login. Instead, a new dedicated `hardware_bans` table in the Core OS database stores HWID hashes only when a ban is explicitly triggered (e.g., via Nuclear Override or Malware Evasion). Login checks now cross-reference this table and enforce bans across both the Core OS and Spoke (Game) databases dynamically without requiring continuous tracking of the user's hardware signature.
- **OS-Wide Mobile Filter Architecture:** Refactored the core `ScreenUtilityBar` engine to use a new `MobileFilterGroup` bottom-sheet on mobile devices. This automatically collapses all secondary filters, dropdowns, and actions into a sleek bottom sheet on over 33 screens OS-wide, massively improving mobile header layouts and reclaiming vertical real estate.
- **Offline Metadata Persistence:** Upgraded the Blueprint (PlaySet) import and export engines to natively support full "Local Dossier" metadata overriding. Custom metadata (like `author` and `url`) assigned to "ghost" strings (missing mods) via the Local Dossier (`sanctuary_local_overrides`) is now dynamically injected into the Blueprint during export. Crucially, when a user imports a Blueprint with this custom metadata, it is securely persisted inside the PlaySet schema as `modMeta`, ensuring custom creator URLs remain fully intact even when shared peer-to-peer. The Ghost Strings and Missing Imports UI alerts now intelligently fall back to the global cloud Registry database for URLs and authors if offline metadata is absent.
- **Blueprint Game Identity:** Blueprint (PlaySet) exports now dynamically embed the `game_id` and `game_name` of the active workspace they were exported from, allowing the OS to accurately identify the target environment when the `.json` file is later imported.
- **Local DBPF Parser Deprecation:** Completely removed the local DBPF Rust parser from the codebase (`dbpf.rs` and `parser.rs`) and migrated the Conflict Radar and Explicitly Local logic to fully rely on the dynamic, DB-driven expansion model. This eradicates flakey parsing errors and unifies the schema architecture for easier game integration.
- **Hub Components Migration:** Completed a massive architectural migration of all legacy Hub components (Oversight, Communications, Chameleons, Settings, Wayfinders, and Masons) to the new `ElevatedHubLayout` and `UniversalCard` standards. This fully eradicates custom layout hacks, unifies the visual hierarchy, centralizes utility/filter bars, and guarantees consistent responsive behavior across the entire OS.
- **Spoke Database UUID Linkage:** Overhauled the data architecture for Game Spoke databases (e.g. `nexus_assets`, `nexus_reports`, `blueprint_reports`) to strictly bind records to active user UUIDs (`author_id`, `reporter_id`) rather than relying exclusively on string usernames. This permanently protects content ownership and telemetry mapping in the event of user profile name changes.
- **Finalized Hub Layout Migration:** Completed the final manual migration phase for `SADefcon`, `KeepersWebLegalEditor`, `KeepersWebNewsEditor`, `KeepersWebDirectivesEditor`, and `SAComplianceOversight`. Ensured all hub components implement the standard `renderLanding` overview tab, numerical badge counts powered by frontend dataset `.filter()` logic, and strict Lexicon key mapping.

### Bug Fixes
- **Elevated Hub Persistence & Role Decoupling:** Fixed an architectural logic flaw where swapping workspaces using the SidePanel or Mobile Navigation did not properly re-evaluate the user's role because the `fetchUserRole` function was locked behind a `didInitBoot` ref. Additionally, decoupled the monolithic `userRole` state into two separate roles: `osRole` (Global OS Permissions) and `userRole` (Game Workspace Permissions). Previously, Global Developers were forcefully elevated to "admin" across all workspaces, causing unauthorized tier tabs (MasonHub, ArchitectHub) to remain visible even when testing as a "citizen". Keepers Core and SADefcon now strictly check `osRole`, while game-specific hubs check `userRole`. Furthermore, added automated fallback logic to instantly kick users back to the `dashboard` view if their newly fetched role drops below the required tier for their currently active Elevated Hub. Also fixed a critical race condition where extracting `fetchUserRole` caused it to run before the application finished fetching the `workspaces` array during boot, resulting in a null database client and forcefully downgrading valid roles (like Wayfinder) to "citizen". Fixed by adding `workspacesLength` as a reactive dependency.
- **TimeCapsule Crash:** Fixed a severe layout breakdown in the TimeCapsule grid where missing dictionary keys (`recent_world_states` and `recent_engine_cores`) in the `en-sims` and `en-sanctuary` lexicons caused the header sections to render as empty, throwing the CSS flexbox and CSS grid alignments entirely out of proportion. Synchronized all missing keys dynamically across the environment lexicons.
- **Spoke Display:** Fixed an issue where the active Spoke (Game Database) was not displaying correctly as the badge or community tag for Custom Themes and Custom Lexicons in the settings, integrating them correctly into the filtered lists.
- **Malware Edits Tracking:** Added a dedicated "MALWARE EDITS" filter to the Audit Logs that leverages a custom Supabase `.ilike()` match against the `mods` target table to seamlessly track threat management actions.
- **Mobile Viewport Height:** Fixed an issue where the mobile bottom navigation bar was pushed off-screen by the browser URL bar by replacing legacy `h-screen` classes with modern `h-[100dvh]` viewports across the root App and Auth wrappers.
- **Public Post Read-Only Mode:** Refined read-only mode in `MasonPostViewer` to completely hide the replies container (including the "No Replies Yet" message) on the landing page public broadcasts, along with hiding interaction buttons (Flag, Profile, Reply Form).
- **Sticky Tooltips Resolved:** Fixed a frustration on mobile where `HoverTooltip` overlays would appear on tap and refuse to dismiss by completely disabling hover tooltips on viewports under 768px.
- **Landing Page Navigation Fixes:** Restored the ability to access the Settings menu directly from the Web Landing Page by adding a persistent button group to the top right of the viewport. Re-enabled the System Dock (bottom bar) on the Desktop Landing Page so that users can access their Settings and Terminal logs even when no active workspace is selected. Added a dedicated 'Settings' button to the Sidebar navigation link list on the Landing Page.
- **SidePanel Refactor:** Migrated all legacy `SidePanelActionFooter` implementations across the OS to the new `headerActions` standard (`PanelHeaderGroup` & `PanelHeaderButton`). Removed all explicit 'Cancel' and 'Abort' footer buttons to streamline the UI, relying exclusively on the built-in top-right close (X) button for cancellations. Cleaned up and fully deprecated the `SidePanelActionFooter` component from the codebase.
- **Landing Page Navigation Returns:** Fixed an issue where accessing Settings or Keepers Core from the root domain would trap the user in those views without a way to navigate back to the landing page. All landing-page specific Sidebar links, the Desktop Logo, and the Mobile Bottom Navigation tabs have been updated to correctly restore the landing page view before attempting to scroll to their targets.
- **Landing Page Layout:** Removed the side-by-side split layout between Workspaces and News on the Landing Page. Sections now stack vertically, allowing Workspaces to utilize the full width of the screen in a clean, responsive grid of horizontal banners.
- **Authentication Guidelines:** Added Privacy and Anonymity Guidelines dynamically to the Authentication UI (Sign Up view) using a sleek, interactive feature list with glassmorphic iconography.
- **DEFCON Modal Clipping:** Fixed an issue where the DEFCON Global Override confirmation modal was being incorrectly clipped by `overflow-hidden` constraints and constrained to the bounding box of its parent layout due to CSS transform rules (`animate-in`). Bypassed the layout stacking context by implementing a React `createPortal` to render the critical alert modal directly to the `document.body`, ensuring it correctly covers the entire viewport on all devices.
- **Mobile Glass Legibility:** Resolved catastrophic GPU tearing and scrolling lag (10fps) on mobile viewports caused by `background-attachment: fixed` on glass elements. The "magic bullet" fix was to keep the high-fidelity desktop "fake blur" (the `::before` pseudo-element with the blurred background image), but forcefully override its attachment to `background-attachment: scroll !important;` on mobile. Due to the heavy 24px blur, the fact that the inner background scrolls slightly out of sync with the main wallpaper is imperceptible, resulting in visually identical, buttery smooth 60fps frosted glass across all mobile devices.

### Visual Overhauls
- **Global Glass Architecture Rebuild:** Solved pervasive Chromium "tearing" and miniaturization bugs with `background-attachment: fixed` on nested glass panels. Refactored the core `.glass-panel` and `.glass-surface` CSS rules to use `background-image` exclusively instead of the `background` shorthand. This prevents the browser from stripping explicit Tailwind `bg-[]` variables and resolves complex stacking context traps.
- **Authentication UI Refresh:** Rebuilt the `AuthWrapper` from the ground up to utilize a native Tailwind `backdrop-blur-[60px]` layer instead of the pseudo-element hacks. Implemented a responsive layout that expands to `max-w-5xl` to display Network Access Guidelines during registration, while remaining a sleek `max-w-xl` for login. Restored logo legibility by removing heavy opacity dampening and adding a custom drop-shadow. Removed `glass-surface` tearing from the Bypass button.
- **StatTiles Color Injection:** Fixed a bug where Dashboard StatTiles failed to inherit their respective theme colors (appearing as empty transparent outlines). Solved CSS z-index and arbitrary compilation limitations by injecting a dedicated absolute overlay div with an inline `backgroundColor: color-mix()` variable, guaranteeing it renders correctly below text but above the background blur.
- **Mobile Landing Page Optimization:** Hid the native desktop client download cards on the Web Landing Page for mobile viewports, replacing them with a custom Lexicon-powered warning card instructing users to visit on a PC to initialize their deployment.
